# GT Detailing

Сайт и админка: Node.js на Render, ветка `gt-detailing-public`.

- Build: `npm run build`
- Start: `node render/server.mjs`
- `/admin` и `/admin.html`: обычный вход по email и паролю, без ChatGPT.
- `/healthz`: проверка работоспособности.

## Серверная конфигурация

`ADMIN_EMAIL` — почта владельца, `ADMIN_PASSWORD_HASH` — соль и scrypt-хеш пароля (`salt:hexhash`, 64 байта), `CMS_SERVICE_KEY` — случайный серверный ключ. Эти значения задаются только в Render Environment. Пароль в Git не хранится. Для сброса задайте новый хеш и выполните деплой; текущие сессии завершатся.

`CMS_ORIGIN` — сервер постоянного хранения GT. Тот же `CMS_SERVICE_KEY` должен быть настроен на сервере хранения. Ключ никогда не передаётся в браузер. Сервер Render сам проверяет сессию и origin запроса, затем обращается к хранилищу. Поддельные клиентские заголовки авторизации игнорируются. Приватные API без сессии недоступны.

Контент, фотографии и резервные копии остаются в прежнем постоянном R2-хранилище GT. Перезапуск Render завершает сессии, но не удаляет данные. Сервер хранения нельзя отключать. При недоступности CMS публичная часть показывает последнюю полученную страницу или исходную сборку; редактор сообщает об ошибке сохранения.

Сессии случайные, только в памяти сервера, срок 8 часов. Cookies: Secure, HttpOnly, SameSite=Strict; выход удаляет серверную сессию. Ограничение неверных входов — 8 попыток с IP за 15 минут. При перезапуске ограничитель и сессии сбрасываются. HTTPS обязателен. Пароль проверяется через scrypt и сравнение постоянного времени.

Бесплатный Render может запускаться после простоя с задержкой.

## Проверка

`npm run build && npm run check && npm run validate && npm run check:render && npm run check:auth`

Тест авторизации использует изолированный локальный сервер и временные секреты: вход, неверный пароль, защита от поддельных заголовков и CSRF, загрузка фото, запись, конфликт ревизий, сохранность контента после перезапуска, выход и ограничение перебора. Опубликованные данные он не изменяет.
